Two kinds of row, one screen. Red is failed — given up on, and it will sit there for ever until somebody presses Retry. Amber is still trying: it has not failed, it is just taking a long time, and it is here so nobody has to wonder where a photograph went.
Attempts is the honest column. Eight means the retry schedule ran out — roughly a day and a half of trying. One means it failed immediately and permanently: a bad visa or a malformed push is never fixed by waiting, so the app does not pretend by retrying.
Retry is safe to press twice. Every push carries a stable reference, so re-sending the same one is meant to be a no-op at NEXT3's end. Whether it truly is depends on NEXT3 honouring that reference — an open question, and the one place duplicates could appear.
Not built, and one column does not exist yet. There is no endpoint that lists these rows and none that retries one. The queue itself is real and running and the index this table needs is already there — but Last tried has nothing behind it: the row stores when it was created, when it is next due and when it was sent, never when it was last attempted, and the next-due value is overwritten while a worker holds the row. That column is a migration, not just a screen. Until all of it is built, the only way to see a failed push is to query the database directly.
